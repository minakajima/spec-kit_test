## User Scenarios & Testing *(mandatory)*

### User Story 1 - ゲーム開始とプレイ (Priority: P1)

ユーザーはブラウザでゲームにアクセスし、開始画面のSTARTボタンをクリックしてゲームを開始します。ゲーム画面では、マウスで自機を操作し、マウスクリック中は継続的に弾を発射してプレイします。

**Why this priority**: ゲームの核となる機能であり、これがなければゲームとして成立しません。最小限の価値を提供するために必要不可欠です。

**Independent Test**: 開始画面からゲーム画面への遷移と基本的なマウス操作による自機移動と射撃機能をテストできます。

**Acceptance Scenarios**:

1. **Given** ユーザーが開始画面にいる、**When** STARTボタンをクリックする、**Then** ゲーム画面に遷移する
2. **Given** ゲーム画面にいる、**When** マウスを移動する、**Then** 自機がマウスの位置に追従して移動する
3. **Given** ゲーム画面にいる、**When** マウスをクリックし続ける、**Then** 自機から継続的に弾が発射される
4. **Given** ゲーム画面にいる、**When** マウスクリックを離す、**Then** 弾の発射が停止する

---

### User Story 2 - 戦闘とゲームオーバー (Priority: P2)

敵機が出現し、敵の弾が自機に当たるとゲームオーバーとなります。プレイヤーは敵を避けながら戦闘を継続する必要があります。

**Why this priority**: ゲームの挑戦要素とルールを提供し、プレイヤーのエンゲージメントを高める重要な機能です。

**Independent Test**: 敵機の出現、衝突判定、ゲームオーバー機能をテストできます。

**Acceptance Scenarios**:

1. **Given** ゲームプレイ中、**When** 敵機が画面に出現する、**Then** 敵機が表示され移動する
2. **Given** 敵機がプレイヤーに向けて弾を発射している、**When** 敵の弾が自機に接触する、**Then** ゲームオーバー画面が表示される
3. **Given** ゲームオーバー状態、**When** ゲームオーバー画面が表示される、**Then** 最終スコアが表示される

### User Story 3 - スコアシステムとデータ保存 (Priority: P3)

自機の弾が敵に当たるとスコアが加算され、最終的なスコアはブラウザのローカルストレージに保存されます。

**Why this priority**: プレイヤーの達成感を提供し、リプレイ価値を高める機能です。データベース不要でシンプルに実装できます。

**Independent Test**: スコア加算とローカルストレージへの保存機能をテストできます。

**Acceptance Scenarios**:

1. **Given** ゲームプレイ中、**When** 自機の弾が敵に命中する、**Then** スコアが加算され画面に表示される
2. **Given** ゲームオーバー時、**When** ゲームが終了する、**Then** 最終スコアがブラウザのローカルストレージに保存される
3. **Given** 過去にゲームをプレイしている、**When** ゲームを再度開始する、**Then** 過去のハイスコアが表示される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは開始画面にSTARTボタンを表示しなければならない
- **FR-002**: STARTボタンクリック時にゲーム画面に遷移しなければならない
- **FR-003**: ユーザーはマウス移動で自機を操作できなければならない
- **FR-004**: マウスクリック中は自機から継続的に弾を発射しなければならない
- **FR-005**: 敵機がランダムなタイミングで画面上部から出現しなければならない
- **FR-006**: 敵機は1.5秒間隔でプレイヤー方向に弾を発射し、曲線的に移動しなければならない
- **FR-007**: 敵の弾が自機に接触した場合、ゲームオーバーになる必要がある
- **FR-008**: 自機の弾が敵に命中した場合、スコアが加算されなければならない
- **FR-009**: 最終スコアはブラウザのローカルストレージに保存されなければならない
- **FR-010**: ゲーム画面には現在のスコアが表示されなければならない

### Key Entities

- **プレイヤー機**: 座標位置、健康状態、弾発射状態を持つ
- **敵機**: 座標位置、移動パターン、破壊状態を持つ
- **弾丸**: 座標位置、発射元（プレイヤー/敵）、移動方向を持つ
- **ゲーム状態**: 現在スコア、ゲーム進行状態、経過時間を管理する
- **スコア記録**: ハイスコア、現在スコアをローカルストレージで管理する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは3秒以内にSTARTボタンをクリックしてゲームを開始できる
- **SC-002**: 自機の動作はマウス移動に対して遅延なく（16ms以内）反応する
- **SC-003**: ゲームは60fpsで滑らかに動作し、プレイヤーが操作しやすい
- **SC-004**: スコアは正確に計算され、ゲーム終了後も保持される
- **SC-005**: 90%以上のプレイヤーが基本操作（移動、射撃）を理解して実行できる
- **SC-006**: ゲームオーバー時に100%の確率でスコアが正しく保存される

## Assumptions

- ユーザーは最新のWebブラウザ（Chrome、Firefox、Safari、Edge）を使用する
- JavaScriptとHTML5 Canvasがサポートされている
- ローカルストレージが利用可能である
- マウスによる操作が前提（タッチデバイスサポートは当初対象外）
- 敵機は画面上部から下方向に移動するシンプルなパターンを想定
- スコア計算は敵撃破1機につき10ポイント加算とする
